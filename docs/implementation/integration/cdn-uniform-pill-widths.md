# CDN change request: uniform DataPill widths in DataGrid

## Requested behavior

Add `uniformPillWidths` to the public `DataGrid` and `Table` props. When true, every rendered `DataPill` in the same visible column uses the width of the widest value in that column. The comparison is made from the rendered pill width, so icons, locale, font, density, and actual text width are included. This is more accurate than raw character count while producing the requested “widest label sets the column’s pill width” result.

The option is disabled by default. CTM will opt in for every grid that uses pill cells after the CDN release is published.

## Source change

In `platform/components/DataGrid/DataGridEngine.jsx`:

1. Accept `uniformPillWidths = false` in the public props.
2. Attach `data-plx-pill-field={field}` to each DataPill generated by the standard `cells="pill"` renderer.
3. After each render where data, visible columns, density, filtering, grouping, page, or width changes, measure the visible pills grouped by `data-plx-pill-field`.
4. Set each measured column width as `--plx-data-grid-pill-width` on the grid root. Use `requestAnimationFrame`; observe the grid with `ResizeObserver`; clean up on unmount.
5. In the DataPill CSS, apply the width only to pills tagged by the DataGrid option:

```css
.plx-data-grid[data-plx-uniform-pill-widths="true"]
  .plx-data-pill[data-plx-pill-field] {
  inline-size: var(--plx-data-grid-pill-width, auto);
  max-inline-size: 100%;
}
```

The current rendered grid should store one custom property per field, for example `--plx-data-grid-pill-width-applicant`. That avoids equalizing unrelated columns.

## Reference implementation

```js
function useUniformPillWidths(enabled, root, dependencies) {
  React.useLayoutEffect(() => {
    const node = root.current;
    if (!enabled || !node) return;

    let frame = 0;
    const measure = () => {
      frame = 0;
      const widest = new Map();
      node.querySelectorAll('[data-plx-pill-field]').forEach((pill) => {
        const field = pill.dataset.plxPillField;
        const width = pill.scrollWidth;
        widest.set(field, Math.max(widest.get(field) || 0, width));
      });
      widest.forEach((width, field) =>
        node.style.setProperty(`--plx-data-grid-pill-width-${field}`, `${Math.ceil(width)}px`),
      );
    };
    const schedule = () => { cancelAnimationFrame(frame); frame = requestAnimationFrame(measure); };
    const observer = new ResizeObserver(schedule);
    observer.observe(node);
    schedule();
    return () => { cancelAnimationFrame(frame); observer.disconnect(); };
  }, [enabled, ...dependencies]);
}
```

When rendering a standard pill cell, set `data-plx-pill-field={column.field}` and use:

```css
inline-size: var(--plx-data-grid-pill-width-<field>, auto);
```

The implementation must leave custom rendered cells alone unless they explicitly opt in with the same data attribute. It must remeasure after virtual rows change, pagination, sort, filter, group, density, locale, and font loading.

## Acceptance checks

- Person, date, numeric, status, and plain text pill columns each equalize only within their own column.
- Columns with no standard DataPill keep their existing layout.
- A long value is truncated only when the grid column itself cannot contain the measured pill; the existing tooltip remains available.
- Keyboard navigation, sorting, filtering, grouping, row virtualization, RTL, and narrow mode continue to work.
- Browser test: change a filter and page size; visible pills resize to the current visible set without horizontal overflow.

## CTM adoption

After publishing a new immutable CDN version, set `uniformPillWidths: true` in `static/ctm/shell-layout.js` and the two direct council DataGrid usages, then bump the CDN version in `tribunal/templates/tribunal/shell.html`.
